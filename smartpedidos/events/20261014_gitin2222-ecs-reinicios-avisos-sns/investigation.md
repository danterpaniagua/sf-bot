## Can the SNS messages be analyzed?
- SNS does not store messages. Delivered messages exist only at the subscriber (an email inbox, a chat space, a Lambda log, an SQS queue). Past messages can be analyzed only if someone has them (pasted emails or an archive); there is no way to replay them from SNS.
- The same information is available at the source, without the messages: (1) ECS keeps stopped tasks for a short time (roughly an hour; not verified for this account) with `stopCode`, `stoppedReason` and each container's exit code; (2) the ECS service events list (last events, e.g. "unhealthy", "task stopped"); (3) CloudWatch `AWS/Events` `TriggeredRules` per rule and `AWS/SNS` `NumberOfMessagesPublished` per topic, which give the volume per hour over 14 days (so the real message count and when it rose); (4) CloudWatch Logs of the containers and ALB target health for the cause of each stop. Task-level history older than the retention is only recoverable if it was logged elsewhere.
- C1 (`scripts/scripts.sh`, read-only) collects (1)–(3) plus the topics' subscriptions with email/SMS endpoints masked.
