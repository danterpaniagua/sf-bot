## Graylog integration — design inputs (carried from the 2170 investigation, same date)

- Target stack: Graylog 5.2.12 on `sf-monitoreo.smartfran.com` (`docs/graylog_infrastructure.md`, 2026-08-12), not `sfcloud-monitoreo`/`cloud-graylog`. Documented inputs: `1514` TXT_UDP, `11514` AWS WAF raw UDP, `12201`/`12202` GELF (transport not stated).
- Precedent Lambda → Graylog: `waf-to-graylog` (`us-east-1`, python3.13, no env vars; code/transport/VPC **not read yet**).
- The escalation Lambda has **no VPC config**: reachability of the Graylog host from AWS Lambda is **unknown** (only checked from the user's machine).
- UDP loses messages silently (per the stack's own doc); a Lambda freezes after returning, so sends must complete before the handler returns; TCP/HTTP GELF would give delivery feedback if such an input exists.
- **Index capacity:** `sp_platform__50` and `graylog_299` were at the 1000-field mapping limit (GITIN-1827/1854, state not rechecked); new fields would be rejected there, so a dedicated stream/index set or already-mapped fields only needs deciding. Creating inputs/streams/index sets is a Graylog change for the user.
- Log shape to follow: the concentrador's JSON (`timestamp`, `service`, `level`, `category`, `message` as `[CATEGORY/LEVEL] event_name`, nested `rest`); nested `rest.*` flattens into new Graylog fields (matters for the field cap).
