# Investigation — 20261013_gitin2221-normalizar-http-paths

**Status:** open, analysis stage. Jira: GITIN-2221 "[OPE] Normalizar HTTP Paths" (https://smartit-ar.atlassian.net/browse/GITIN-2221), a subtask of GITIN-2218 "[CLOUD] Visibilidad Graylog" (https://smartit-ar.atlassian.net/browse/GITIN-2218) (user-stated). Scope (user): normalize the HTTP `Path`. Origin: in GITIN-2218 the Endpoints tables on the Operations dashboard group by `Path`, and routes with ids in the path (e.g. `WalletCredentials/<id>`) split into many rows. Not defined yet: whether the scope is only the application logs (the dashboard's streams) or also `Path` from `AppServiceHTTPLogs`. Nothing has been changed in any system; the Jira body was not provided.

## Analysis (read-only; `routes_extract.py`, `routes_match.py`, `data/routes-origin-main.json`, `data/routes-extract-log.txt`, `data/observed-paths.txt`, `data/routes-match-test.txt`)
- Request (user): a new key `NormalizedPath`, derived from the Controllers' code, e.g. `/api/v1/WalletCredentials/2024771231` and `/api/v1/WalletCredentials/1357013702` both give `api_v1_WalletCredentials` (route parameters removed, `/` replaced by `_`).
- Source read: `SmartFran.Cloud` `origin/main` @ f88d6d743 (2026-10-07); the local working tree is `main` @ d969856fa (2026-09-30) and was not used. 128 `*Controller.cs` files, 827 routes extracted (class `[Route]` + method `[Http*]` templates, `[controller]`/`[action]` substituted), 334 with route parameters, 792 distinct templates. The extractor is a regex over attributes, not a Roslyn parse: routes defined any other way (conventional routing, minimal APIs, SignalR hubs) are not included.
- Test of a template matcher (literal segments case-insensitive, `{x}`/`{x?}`/`{*x}` parameters, the template with most literal segments wins) on the 69 distinct paths already pulled from Graylog (C2–C5): 61 matched and 8 did not. Unmatched: `/`, `/_blazor`, `/_blazor/disconnect`, `/_blazor/initializers`, `/_blazor/negotiate`, `/health`, `/notificationsCloud/negotiate`, `/robots933456.txt` (Blazor, health, SignalR hub and a scanner request: not controller routes). Matches include `/api/v1/WalletCredentials/<id>` → `api_v1_WalletCredentials`, `/api/v1/Franchisee/GetCompleteByCode/<hash>` → `api_v1_Franchisee_GetCompleteByCode`, `/api/v1/Items/GetCacheByIdAsync/<n>` → `api_v1_Items_GetCacheByIdAsync`, `/api/Tenant/<hash>` → `api_Tenant`, `/api/Tenant/Organization/<org id>` → `api_Tenant_Organization`.
- The 69 paths are a sample (top paths of a few pulls), not all traffic; no coverage figure for the full traffic.
- Options (not decided): (A) in the application, take the route template of the matched endpoint (ASP.NET `RouteEndpoint.RoutePattern.RawText`) in the shared request logging, strip the `{...}` segments, and log it as a property; exact, no table to maintain, needs a Dev change and deploy in each service, plus promotion of the new property in the Logstash conf (as done for `Path` in GITIN-1940). (B) in Logstash, a table of the route templates generated from the controllers (these scripts) and a filter that sets `NormalizedPath`; no deploy of the services, but the table must be regenerated when routes change, and non-controller paths need a fallback value (cardinality). In both, only new messages get the field.

## Option B — Logstash patch (first pass applied 19:31 UTC; later passes below)
- Live config read twice (C1 and C2, 2026-10-13 19:19 and 19:22 UTC; secrets redacted at source, 0 left): `/etc/logstash/conf.d/azure-eventhub-to-graylog.conf`, 41,615 bytes, modified 2026-09-23 13:56 (the GITIN-2098 version), sha256 728bb77c…c56a, 809 lines; Logstash 8.19.18; `pipelines.yml` loads `/etc/logstash/conf.d/*.conf` (so a backup must not end in `.conf`); service active. `Path` is set in four places: Event Hub apps (line 366), Sales direct-GELF (381), `AppServiceHTTPLogs` `CsUriStem` (429), PosWasmRelay `EntryProperties` (738).
- Patch (`scripts/logstash/normalizedpath.patch`, 81 lines): a Ruby filter inserted at line 767, after all the blocks that set `Path`, before the final `properties` step. `init` loads `/etc/logstash/normalized-paths.json` (796 templates: 792 from the controllers plus 4 extras for Blazor, health, the SignalR hub and the root, added by hand); `code` sets `NormalizedPath` from `Path` (most-literal template wins; no match → `unmatched`; a 20,000-entry cache of raw path → value). It applies to every event that has `Path`, so also to `AppServiceHTTPLogs` (scope question still open).
- Local checks: the patch applies to the live copy and reproduces the expected file; `ruby -c` passes on both parts; the same block run in Ruby 3.2 gives identical results to the Python matcher on the 69 observed paths (the only differences are the 7 non-controller paths now covered by the extras; `/robots933456.txt` → `unmatched`). Not tested: under Logstash/JRuby itself (`logstash -t` is the first step of `deploy.sh stage`), and not at message rate.
- `deploy.sh` (modes `stage`, `apply`, `rollback`) is written, not run. `stage` installs the table file and tests a patched copy; `apply` backs up the live config as `…conf.bak-GITIN-2221`, patches, tests, and restarts only if the test passes; a failed test restores the backup. Restart behavior of the Event Hub input (checkpoints in the storage account) was not verified here; earlier tickets (GITIN-2034, GITIN-2098) restarted the same service.
- Unverified: whether `NormalizedPath` will be a keyword in the OpenSearch mapping like `Path` (expected, since Graylog maps strings the same way); only new messages get the field.
